# 交通信号控制平台项目总体规划

## 1. 项目基本信息

- 项目名称：交通信号控制平台
- 英文名称：Traffic Signal Control Platform
- 项目目录：D:\Projects\traffic-signal-control-platform
- 仿真地点：天津市河东区新开路与华龙道交叉口
- 开发环境：Windows、VS Code、Docker、SUMO

- 数据库：PostgreSQL
- 版本管理：Git

## 2. 项目总体目标

建立一个基于 SUMO 的单路口交通信号控制仿真平台。

实现道路、车道、机动车、交通信号灯、信号机和倒计时的仿真展示。

支持通过浏览器管理信号相位、调整信号配时，并实时观察信号灯变化和机动车通行情况。

## 3. 核心功能

1. 单个十字路口道路、进口车道和出口车道仿真。
2. 四个进口方向分别设置独立左转、直行、右转车道。
3. 机动车生成、跟驰、直行、左转、右转、停车及让行。
4. 四类受保护交通流的信号控制：南北直行、南北左转、东西直行、东西左转。
5. 四个业务通行阶段各包含绿灯和黄灯，共形成 8 个 SUMO 绿/黄灯阶段。
6. 红灯最后 10 秒、绿灯最后 8 秒及黄灯全程倒计时。
7. 右转车辆始终采用独立让行规则，不属于四类受保护信号阶段；在满足安全让行条件时可以通行，但不得获得优先通行权。
8. 浏览器实时展示路口、车道、车辆、信号组和倒计时。
9. 信号控制支持 AUTO（自动）与 MANUAL（手动）模式，并独立支持控制启用/停用。
10. 保留二维路口视图，增加二维/三维视图切换。
11. REST API、WebSocket 实时通信、仿真运行管理和控制记录持久化。

以上为项目总体目标，不代表所有功能均已实现或通过验收。具体实施状态以各阶段代码、测试和验收证据为准。

### 9.2 当前仿真基线与新增交通组织要求

当前业务控制基线为 4 类受保护交通流、8 个 SUMO 绿/黄灯阶段：

- 南北左转绿灯/黄灯。
- 南北直行绿灯/黄灯。
- 东西左转绿灯/黄灯。
- 东西直行绿灯/黄灯。

每个业务阶段包含绿灯和黄灯，SUMO 共 8 个绿/黄灯阶段。

四类受保护业务阶段的顺序固定如下：

| 阶段 | 业务阶段 | 放行交通流     | SUMO 阶段索引 |
| ---- | -------- | -------------- | ------------- |
| 1    | 南北左转 | 北、南进口左转 | 0 / 1         |
| 2    | 南北直行 | 北、南进口直行 | 2 / 3         |
| 3    | 东西左转 | 东、西进口左转 | 4 / 5         |
| 4    | 东西直行 | 东、西进口直行 | 6 / 7         |

每个业务阶段的绿灯后必须执行对应黄灯。业务阶段顺序、SUMO 阶段索引和前后端阶段编号必须保持一致。

四个进口方向均设置独立右转车道。右转不属于四类受保护信号阶段，始终采用独立让行规则，不获得优先通行权。当前 SUMO TLS 程序将四个右转连接（linkIndex 0、5、10、15）在全部八个阶段设置为小写 `g`，表示让行绿灯，而不是受保护绿灯或无条件通行。车辆接近冲突区域时必须减速观察；如存在行人、非机动车或其他冲突交通流，应停车让行，待冲突解除后方可通行。

当前记录的 SUMO 测试基线时长为：

- 南北直行绿灯：40 秒。
- 南北左转绿灯：20 秒。
- 东西直行绿灯：40 秒。
- 东西左转绿灯：20 秒。
- 四类黄灯：各 3 秒。

以上数值是现有仿真测试基线，不代表真实路口最终配时已经验收。

右转独立车道、让行行为及其与行人/非机动车的冲突关系，仍需在调整 SUMO 路网后通过 controlled-links、冲突矩阵和实际仿真专项验证。

### 9.4 进度标记原则

文档中“已实现”只表示代码中已有相应实现；“已验证”必须有实际运行或自动化测试证据。

规划接口、规划组件和验收项不得描述为已经完成。

阶段验收必须区分：

- 代码实现：代码中已经具备相应功能。
- 自动化测试通过：对应测试实际执行并通过。
- 真实环境验证通过：在目标运行环境中完成实际验证。
- 待验证：尚无足够证据证明验收通过。
- 已知问题：已经发现但尚未解决的问题。
