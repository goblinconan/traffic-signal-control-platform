# SUMO 仿真设计

> 版本：V2.1（四类保护式交通流及右转让行目标设计）  
> 对应需求：`docs/01-requirements.md`

本文描述目标仿真设计。现有 SUMO 网络和信号状态字符串属于阶段性测试基线；车道拓扑或连接关系变更后，必须重新生成并验证，不能直接沿用旧 `linkIndex`。

## 1. 网络与配置来源

- 当前仿真配置入口为 `simulation/config/intersection.sumocfg`。
- 网络文件位于 `simulation/network/`，路由文件由 SUMO 配置引用。
- 可使用 OSM 数据建立基础网络，再通过 `netconvert` 转换并人工校正。
- 修改 `.tll.xml` 后必须重新运行 `netconvert` 更新 `.net.xml`；不能假设 SUMO 会自动合并。
- 无法从来源数据确认的车道、转向或几何参数必须标记为仿真假设。

## 2. 目标进口车道组织

四个进口方向均须分别设置：

1. 独立左转车道。
2. 独立直行车道。
3. 独立右转车道。

左转、直行和右转不得共用同一条进口车道。每条进口车道必须明确关联其 SUMO lane ID、可用出口连接和业务转向类型。

目标交通组织要求与来源路网不一致时，必须记录差异并校正 SUMO 网络；不得仅依赖 `lane_index` 或车道编号推断转向。车道拓扑变更后，应重新生成 controlled-links 映射和信号状态字符串。

## 3. 八个 SUMO 绿/黄灯阶段

第一版包含四类受保护业务通行阶段，每个绿灯阶段后紧接对应黄灯阶段：

| index | 阶段 ID              | 业务信号组 | 当前测试基线 |
| ----: | -------------------- | ---------- | -----------: |
|     0 | `NS_LEFT_GREEN`      | 南北左转   |          20s |
|     1 | `NS_LEFT_YELLOW`     | 南北左转   |           3s |
|     2 | `NS_STRAIGHT_GREEN`  | 南北直行   |          40s |
|     3 | `NS_STRAIGHT_YELLOW` | 南北直行   |           3s |
|     4 | `EW_LEFT_GREEN`      | 东西左转   |          20s |
|     5 | `EW_LEFT_YELLOW`     | 东西左转   |           3s |
|     6 | `EW_STRAIGHT_GREEN`  | 东西直行   |          40s |
|     7 | `EW_STRAIGHT_YELLOW` | 东西直行   |           3s |

顺序为 `0→1→2→3→4→5→6→7→0`。每个南北信号组同时覆盖北向和南向同类交通流；每个东西信号组同时覆盖东向和西向同类交通流。用户已确认南北相反方向左转同时放行、东西相反方向左转同时放行；仍须以目标 SUMO 网络冲突矩阵作最终技术验证。该顺序是当前正式目标顺序；历史诊断文件中曾使用不同阶段排列，历史数据仅作当时修复证据。

保护式左转阶段必须确保对应方向直行连接为红灯。例如 `NS_LEFT_GREEN` 期间，南北直行连接不得同时获得绿灯；`EW_LEFT_GREEN` 期间，东西直行连接不得同时获得绿灯。

表中时长是现有 SUMO 测试基线，不代表最终实际配时。四类绿灯和黄灯时长分别配置，红灯总时长按完整周期计算。

## 4. 右转红灯让行规则

四个进口方向的右转车辆使用各自独立车道。右转不属于四类受保护放行阶段，而是始终采用独立让行规则，不获得优先通行权。当前 SUMO TLS 程序将四个右转连接（linkIndex 0、5、10、15）在全部八个阶段设置为小写 `g`；该灯色表示允许通行但必须让行，不表示受保护绿灯或无条件通行。

仿真行为要求：

- 右转车辆接近转弯及交叉冲突区域时减速观察。
- 与行人、非机动车或其他车辆存在冲突时，右转车辆必须停车等待或继续减速，不能抢占优先权。
- 冲突对象离开冲突区域后，右转车辆才可继续通过。
- 无冲突时，右转车辆也应以适当低速通过冲突观察区域。
- 右转不得因为独立车道而获得无条件优先权。

当前测试基线中，四个右转连接由 SUMO TLS 控制，并在全部八个阶段使用小写 `g` 表示次要绿灯/让行通行；不得使用大写 `G` 赋予右转优先通行权。该静态信号配置本身不能证明车辆已执行减速、停车和让行，必须结合 controlled-links、冲突关系及车辆轨迹验证。

为验证让行规则，测试路网必须包含或构造行人、非机动车及其他冲突交通流进入右转冲突区域的场景。若正式场景尚未建模行人/非机动车，必须明确标记为待补充的测试场景，不能声称让行行为已经验收。

## 5. Controlled links 映射

启动时读取：

```python
links = traci.trafficlight.getControlledLinks(tls_id)
```

为每个 `linkIndex` 建立以下映射：

- from lane / to lane。
- 进口方向。
- 转向类型（左转、直行、右转）。
- 业务信号组。
- 控制类型（保护式、让行式、无信号控制）。
- 冲突连接关系。

要求：

- 状态字符串长度必须等于 SUMO 受控连接数。
- 长度匹配只是必要条件，不代表灯色语义正确。
- 每个 linkIndex 必须逐项验证，不得假设一个业务信号组只对应一个 linkIndex。
- 右转连接不得仅因 lane index 固定而被设为永久优先绿灯。
- 车道拓扑变化后必须重新读取 controlled links、冲突矩阵和状态字符串。
- 对向左转同时放行必须验证其连接确实不冲突；若目标网络发现冲突，先修正网络或控制方案，不得强行放行。

历史 20 位状态字符串和阶段记录见 `docs/2026-11-11-SUMO-left-turn-fix.md`。该文件记录的是历史修复证据，不代表车道结构变更后的 `linkIndex` 仍保持不变。

## 6. 黄灯过渡专项

2026-11-11 诊断记录存在 `Missing yellow phase` 警告，涉及 `tl-index 0` 和 `tl-index 5`，分别在 phase 0→2、phase 4→6 附近出现。该问题必须继续跟踪，不能因状态字符串长度匹配而视为已解决。

验收要求：

- 明确警告对应的 from/to connection。
- 解释其在业务阶段中的转向含义。
- 核实是否存在绿灯直接转红灯或黄灯被跳过。
- 必要时调整受控连接分组或阶段状态，但不得破坏已验证的左转路线。
- 通过真实 SUMO headless 测试及浏览器运行验证。
- 保存修复前后日志和验证结果。

## 7. 车辆与跟驰

- 车辆生成和路线由 SUMO route/flow 文件定义。
- 跟驰、变道、车辆运动和红灯停车由 SUMO 执行。
- 后端读取车辆位置、角度、速度及可用尺寸属性。
- 前端不得自行规划车辆路线或修改车辆运动。
- route 中多个 flow 应按 SUMO 要求的发车时间顺序排列；新增或调整 flow 后必须检查排序警告和实际生成车辆。
- 右转车辆的减速、停车和让行必须通过 SUMO 真实车辆行为验证，不能只检查 TLS 灯色。

## 8. 时间、生命周期与并发

- 唯一仿真时间基准为 `traci.simulation.getTime()`。
- 信号阶段开始时间、结束时间和剩余时间均基于仿真时间。
- 仿真暂停或停止时不得继续推进状态机。
- 每次启动新仿真必须重置或重新构建与本次运行关联的状态机、阶段时间和 SUMO 初始灯色。
- stop 与后台 step 之间必须同步，防止关闭 TraCI 时仍有线程执行仿真推进。
- TraCI 同一连接的所有读写应采用统一串行执行或经过验证的互斥机制。

## 9. AUTO/MANUAL 与控制启停

- AUTO：后端状态机按八个 SUMO 阶段及配时自动推进。
- MANUAL：切入时当前绿灯完成原定时长并执行完整黄灯，随后进入全红；无人工请求时持续全红。
- 手动命令不能直接设置任意 SUMO 状态字符串；合法业务阶段请求由后端校验，并在全红安全边界启动。
- 控制 ENABLED/DISABLING/DISABLED 与 SUMO 仿真 RUNNING/STOPPED 分离。
- DISABLED 请求后立即拒绝新的控制命令；当前绿灯及完整黄灯结束后，所有 controlled links（包括原小写 `g` 右转 link）置为红灯。
- DISABLED 后 SUMO 继续运行，信号控制状态机保持全红，不自动推进。
- 重新启用时 AUTO 从 NS_LEFT 恢复；MANUAL 继续全红等待人工请求。
- 新一轮 SUMO 启动时重置控制域为 ENABLED/AUTO。
- 以上行为按 `docs/ADR-014-control-mode-and-disable-policy.md` 执行。

## 10. 网络几何与二维/三维可视化

为二维/三维共享数据准备以下网络几何：

- edge/lane shape 与 lane width。
- junction shape。
- internal lane 与 connection。
- 左转、直行、右转车道及转向属性。
- 停止线位置。
- traffic light/link 与空间位置关联。
- SUMO 坐标原点及前端坐标变换。

静态网络数据与动态车辆/信号状态分离。三维场景只渲染后端提供的网络和仿真状态，不另行模拟交通规则。

## 11. 待验证事项

- 四个进口方向独立左转、直行、右转车道是否已在目标网络正确建立。
- 对向左转同时放行的实际冲突矩阵验证。
- 四个右转连接在全部八个阶段使用小写 `g` 时，车辆是否能够正确减速、停车，并向行人、非机动车及其他冲突交通流让行。
- `Missing yellow phase` 两条警告的根因及修复。
- 八阶段动态配时的安全生效边界。
- 仿真停止/重启时状态机与 TraCI 生命周期。
- TraCI 并发访问模型。
- 静态网络几何 API/首帧加载方式。
- SUMO 与 FastAPI 的最终部署拓扑。
